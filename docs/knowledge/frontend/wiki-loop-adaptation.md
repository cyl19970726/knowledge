# 把 Ingest / Query / Lint 接入同一认知工作台

2026-11-02 · 以已合并 PR8 的 `2f66ba174bbd47be92d0bbdc238159d33c5a74f8` 为前端起点。本页是功能适配合同；继承[联读体验](experience.md)、[设计系统](design-system.md)和[工作台定义](workbench-plan.md)，不替代它们。2.5D 继续遵循[单独实验交接](handoffs/2p5d-experiment-20261102.md)，本次不实现或开启实验入口。

用户已确认首版优先“围绕问题查知识、联读并核对依据”。默认问题视角承接这条主路径；来源入库与维护通过相关认识、待核问题和候选修订提供支持。

用户应能解释：我在研究什么；哪些已有认识与它有关；本轮实际读了什么；新结果处于哪一阶段；正式知识究竟改变了什么。底层 API、任务或模型步骤分别留账，界面围绕同一个问题组织这些记录。

## 对象身份决定怎样展示

| 对象 | 用户需要理解 | 工作台中的表达 |
| --- | --- | --- |
| 正式 Wiki 页 | 有条件、有依据且有准确版本的一条认识 | 当前认识、可读正文和条件/反例；星图只定位，不能替代全文 |
| 原件与报告 | 支撑认识的原依据，各自有 owner、版本、锚点与权限 | 来源文档形状、来源阅读与准确定位；读取报告文本不等于看过原视频 |
| 提及与实体 | 文中出现的名字、对象是否同一件事仍需消歧 | 源文提及标记与“提案/未消歧”状态；不能仅凭提取表面词就新增正式实体节点 |
| 临时问答 | 对本次实际读集的回答 | 问题上下文中的有据答案，注明读集、条件、反例与未覆盖；不会自动成为正式 Wiki |
| 编纂候选 | 有新解释，等待独立审阅 | 独立候选标记、准确 before/after、继承依据与审阅入口；不混入当前正式星图 |
| 研究与维护记录 | 为什么触发、实际执行什么、得到什么结果 | 研究笔记中的阶段与待办摘要；完整步骤、费用、原键和方法可以展开核对 |
| 搜索与图投影 | 当前允许返回的阅读范围 | 范围与遗漏说明；布局距离、群落、光晕和索引 ready 都不表达可信度 |

支持、挑战、背景和导航沿公开关系合同表达。相似候选、判断器输出和共享来源组各有用途，不自动画成正式支持边；尚无命题锚点时明确说明缺口。

## 三种操作怎样进入现有体验

| 操作 | 用户看见的主线 | 展开后能核对什么 |
| --- | --- | --- |
| Ingest | 来源已登记 → 后台研究中 → 候选/提案无变化/待补证 → 独立审阅结果 | 准确报告、规划提案、旧页、关系判断与编纂读集；登记成功不写成“正式知识已更新” |
| Query | 输入问题 → 找到已有认识 → 实际读页/必要来源 → 临时答案 → 返回联读 | 用户选择、候选返回与实际读集分开；引用指向准确版本，预算/权限不足的部分可见 |
| 回答后研究 | 明确勾选回答中的结论 → 输入新问题与费用上限 → 待审候选 → 返回原答 | 原回答指纹与所选结论、完整原读集、新问题、原键、候选及其审阅状态；回答不充当第二份独立证据 |
| Lint | 与当前认识有关的待核对事项 → 定位问题与依据 → 研究或处理结果 | 到期、断链、缺少关联、依据失效等结构发现；语义发现与修订另行研究，不把提示当结论 |

星群帮助发现联系，问题视角帮助联读、问答和判断，演化帮助解释修订。维护收件箱是完整记录入口；从事项打开候选、正文或来源后，应能返回原问题和原来的位置。

## 共同上下文与状态

共同上下文包含空间、用途、当前问题、准确选择、焦点版本、视角、渲染方式和相机/阅读位置。2D、3D、列表只改变表现，星群、问题、演化只改变阅读视角；它们不能各维护一份知识身份。

“用户选中”“检索找到”“实际读入”“候选已形成”“已发表”分别显示。问答将受支持的联读选区作为带摘要的准确引用提交，服务仍按权限与读取额度裁定；未开放该能力的旧服务只按问题检索，界面必须说明选区未自动纳入。提交后冻结问题和准确选区，之后移动星图或增删联读项不改变已提交记录；回答只把真实读取成功的版本列为依据，并逐项显示排除与缺口。选区或加载动画不代表阅读完成；模型提案不代表关系已审定；任务完成也可能是拒绝、取消或仍需补证。无法确认的结果显示待核对及已知/未知费用，提供按原记录只读核对的动作，不自动再发付费请求。

从回答继续研究是独立的显式操作：只在当前答案为 `answered`、有指纹且实例允许 `researchAnswer` 时显示可用入口。用户选取 claim 索引并填写后续问题；编纂结果保留原回答问题和指纹，显示的新研究问题不得被旧答案文本替换。仅选中的结论进入研究提示，原回答实际读过的全部准确 Wiki 与来源仍纳入新编纂的权限和额度检查；来源不占 Wiki 页数 `limit`，全部证据总数仍受 100 上限约束。默认费用上限 0 USD，用户须明确提高上限；合成标识不可当成真实模型回答。候选页应有回到原答的入口，独立审阅之前不显示成正式认识。

研究原键与调用者输入只存在当前标签页的会话记录，不存 token、答案或原文。刷新、返回候选或网络结果未知时，冻结同一意图，只读核对原键/原 ID；重新认证后恢复原问题与选择，不自动提交第二次。当前答案不可读但原编纂已发表或拒绝时，仍可经编纂原键查看受权的历史 origin；来源撤权须隐藏历史内容。旧服务没有答案指纹或未声明研究能力时，不展示可提交的研究入口。

切换空间、身份或用途时清除不再获权的派生内容，并中止旧请求。正文、来源与候选的读取继续验当前权限；演化中将已发表历史和受权候选预览分开，未发表版本没有正式发表时间。

## 适配验收

1. 保留 PR8 主线的默认 3D、2D、列表、星群/问题/演化、联读、减少动态与来源返回行为。
2. 用同一案例走完“问题 → 旧认识与来源 → 回答 → 新来源后台研究 → 准确候选 → 独立审批或拒绝 → 下一轮查询 → 演化核对”。
3. 对照用户选择、实际读集和输出引用，能说明哪些未读、哪些只是导航、哪些来自同一原件；不为视觉完整补造节点、关系或来源。
4. 验证拒审、待补证、撤权、取消、过期租约与未知费用；不能把它们展示成成功发表或零成本。
5. 在桌面与390px完成相同阅读任务；检查长中文、焦点、暗色对比、返回位置、键盘可达与页面横向溢出。工程、视觉、真人理解和真实语义分别记证据。

本地回答研究的合成浏览器走查覆盖 1159px 与 390px 无横向溢出、候选返回和丢响应刷新后原键只读恢复；390px 触点尺寸及系统减少动态尚未验收。真实模型、旧页失效 `recompile`、自动答案任务化、统一实体消歧与外部来源发表保证仍按[当前状态](../current-state.md)逐项验证。


## 设计工作如何服务问题驱动主线

用户要求在必要时使用 Product Design，并说明页面取舍。已有 PR8 视觉目标时，先以当前页面截图核对阅读顺序、主操作、状态与返回路径，沿现有设计语言修正；新增页面或需要探索新方向时，再根据明确的用户任务生成视觉方案并实现。现有代码、截图和设计系统就是本轮的参照，不因增加一个能力重建另一套界面。

本轮把继续研究入口放到回答附近，研究结果出现后突出打开候选；新一次提交通过显式入口展开。原问题、后续问题、实际读集和候选状态分别显示；版本标识与操作记录进入可展开详情。具体截图、可见问题和验收限制见[页面审视记录](../evidence/answer-research-design-audit-20261102.md)。


## 已选的星图与正文分栏

用户于2026-11-02选择[第二张视觉提案及其可调分栏修订](../evidence/starmap-research-designs-20261102.md)：问题驱动的正文在左，既有星图常驻右侧。分隔边界支持拖动、键盘调整、比例记忆及复位，另有放大星图与恢复联读；窄屏顺序展开，维持同一问题、准确选择、引用与阅读位置。尺寸变化不创建新问答或编纂操作。

## 可调分栏本轮实现与验证

共享分栏已用于问答/星图（默认52/48）和常规星图/研究笔记（默认72/28），包括拖动、键盘、最小宽度、独立比例偏好、复位、放大及恢复。浏览器验证放大恢复保持相机与阅读位置，切换2D/3D/列表保留回答，刷新后恢复冻结问题、45%比例及原研究；389px顺序展开无横向溢出。候选经准确读取后显示新增条件，不加入正式图；首次读取和审阅刷新都核对候选目标及scope。
