## 1. 验收结论的定义

只允许四种结论：

| 结论 | 含义 |
| --- | --- |
| `not_run` | 尚未完成该检查或证据不可复现 |
| `blocked` | 有P0/P1未关闭，或评分/任务未达门槛；可以展示但不视为完成 |
| `passed_local` | 工程、语义、视觉与响应式自动/人工检查通过，等待用户视觉确认 |
| `passed` | `passed_local` 的全部条件满足，且用户明确接受本轮视觉结果 |

不得使用“基本通过”“视觉接近”“除细节外通过”。任何硬阻断项未关闭时，最终结论必须为`blocked`。

## 2. 硬阻断项

以下检查由实现者和独立复核者分别执行。出现任一项即不得进入`passed_local`或`passed`。

| 级别 | 阻断条件 | 判定证据 |
| --- | --- | --- |
| P0 | 页面补造节点、关系、来源、群落摘要、时间或数量；把未知依据显示为已知；候选进入正式版本线 | 与Graph/History/Compare当前返回逐项对照；记录节点、边、source ref、version id和时间来源 |
| P0 | 权限、用途或读取范围变化后仍展示旧图；空结果被解释成全库不存在 | 切换作用域/权限或读取已知空结果，检查缓存和文案 |
| P1 | 桌面主画布被非必要界面压缩，关键构图无法在1440×1024首屏完整出现 | 同尺寸截图与布局测量 |
| P1 | 当前认识、两条支持、挑战、关键群落或来源出现无法解释的遮挡、裁切或不可读重叠 | 桌面三视角实拍；标签框碰撞记录 |
| P1 | 手机发生页面级横向溢出，或无法用列表完成同一阅读任务 | 390–391 CSS px视口；`scrollWidth === clientWidth`；列表任务记录 |
| P1 | 稳定构建正常切换三视角时白屏、崩溃、WebGL上下文丢失或关键操作无响应 | 生产预览控制台、10次切换和错误记录 |
| P1 | 键盘无法抵达图谱控制、列表入口和关键操作，或减少动态效果下仍有强制动画 | Tab顺序、可见焦点、`prefers-reduced-motion`实拍/状态 |
| P1 | 动效阻塞操作，拖拽无法中断相机过渡，或用户无法暂停/跳过入场序列 | 中间状态与中断测试 |

## 3. 桌面构图预算

基准视口为1440×1024 CSS px。数值是验收区间；布局若使用不同列宽，必须证明中央星图仍达到相同视觉占比。

| 项目 | 通过目标 | 测量方法 |
| --- | --- | --- |
| 中央星图宽度 | 占视口56%–61%，约806–878 px | 截图中主图卡左右边界 |
| 右侧笔记宽度 | 280–330 px，独立滚动 | DOM边界与截图 |
| 图面起点 | 首个可交互图谱内容距页面顶部不超过190 px | 顶栏、标题、视角和工具控件总高度 |
| 图面可视高度 | 桌面至少620 px；首屏保留图例/范围入口 | 截图与DOM高度 |
| 页面滚动 | 1440×1024下主任务不产生整页竖向滚动 | `scrollY`、页面高度和滚动测试 |
| 安全边距 | 主要星点、标签和来源距画布边缘至少16 px | 边界框检测 |
| 常驻文字标签 | 星群默认状态不超过8个；问题视角不超过5个 | DOM标签计数 |
| 文字最小值 | 辅助字不小于11 px，主要标签12–16 px；关键正文不低于13 px | 计算样式与截图 |
| 单行摘要 | 群落副标题、工具状态和底部范围摘要默认不换行成两行 | 截图与元素高度 |

标题、视角切换和图谱工具应形成不超过两段的控制区。若仍需要三层，第二、三层必须合并视觉背景，避免像三个独立工具栏叠放。

## 4. 三视角专项验收

### 星群

- 群落数量与当前真实分组一致；本次基线为6个有界群落，选中群落由“当前认识”标识承担标题职责，因此同时显示5个群落标题。不得为了凑参考图固定成5群。
- 4个可读来源必须与各自主导连接区域可辨；同一来源到同一认识的多条关系不能重复增加大小、光晕或群落分数。
- 138条返回关系全部绘制，或未绘制关系有明确数量和原因；当前基线要求全部绘制。
- 7条跨群关系中，支持/挑战以增强桥梁显示；导航保持可区分的弱线型。不得把导航写成论证支持。
- 当前认识、最多3条直接支持/挑战路径和群落标题同时可见时，不能互相覆盖。
- 四个来源使用独立形状和光晕层级；来源位置只表示当前投影的主要关联区域，不表示权威或独立证据数量。

### 问题

- 当前认识、2条支持、1条挑战和实际返回来源在首屏形成清楚的A/B/C/D阅读路径。
- 支持、挑战和背景关系使用不同线型/文字；依据未知必须可见。
- 背景网络保留空间上下文，但不得与前景标签争夺对比度。
- 正文、来源与返回操作可用；返回后恢复问题、选择、视角和相机。
- 没有实际返回的来源或关系时显示缺口，不用装饰补齐。

### 演化

- 只显示已发表准确版本；本次首屏基线为2版。候选独立放置并标明未发表。
- 层叠、透视和入场动画帮助看出版本顺序，不表示可信度或整网快照。
- 比较动作只接受两个准确已发表ref；字段差异和原因分开说明。
- 当前接口没有整网`asOf`或cursor时，界面明确说明不能展示整网历史。

## 5. 视觉语言与动效

| 维度 | 通过条件 |
| --- | --- |
| 星点 | 明亮内核、柔和径向光晕和状态环形成清楚层级；普通点不持续闪烁；不使用整屏Bloom糊化标签 |
| 色彩 | 群落色温稳定且低饱和；选中、支持、挑战和候选各有文字或形状辅助；琥珀只承担挑战语义 |
| 纵深 | 默认镜头有可感知但克制的侧向/俯视角度；节点前后层不牺牲标签可读性 |
| 卡片 | 当前认识、A/B/D和来源卡采用一致的边框、圆角、字级和间距体系，不出现四套相似组件 |
| 留白 | 群落之间保留呼吸空间；空白不做无意义粒子填充；主焦点周围的信息密度低于边缘网络 |
| 入场 | 一组600–800 ms的群落/桥梁/焦点序列；不得循环播放 |
| 交互 | 选择反馈100 ms内开始；镜头与标签替换250–350 ms完成；拖拽立即取消平滑镜头 |
| 减少动态 | 直接呈现最终状态；无相机缓动、无层错峰、无必要以外的透明动画 |

## 6. 验收任务

视觉通过必须同时完成以下任务。证据记录任务、准确数据、操作与结果，不以“看到了”代替。

| 任务 | 通过条件 |
| --- | --- |
| T1 找到焦点 | 无需打开详情即可指出当前认识及其所属群落 |
| T2 解释来路 | 能指出2条准确支持和至少1条挑战，并区分导航关系 |
| T3 查来源 | 打开一个来源，读到准确版本/锚点并返回原图；返回后焦点、选择和位置不丢 |
| T4 跨群阅读 | 能指出至少1条真实跨群支持/挑战，且说明它来自哪两个群落 |
| T5 视角切换 | 星群→问题→演化→返回，不丢失同一准确选择；2D/列表提供等价入口 |
| T6 联读选择 | 选择两条准确认识，满额时第三条有明确限制；不得静默替换 |
| T7 手机任务 | 在390–391×844完成定位、查看当前认识、切换问题并使用列表打开正文 |
| T8 辅助技术 | 关键按钮、列表和当前状态可通过键盘到达；屏幕阅读器可读到“当前认识”等真实文本 |

## 7. 响应式与可访问性

- 桌面：1440×1024和1024×768均无页面级横向溢出；主任务在视口内可完成。
- 手机：390–391×844下`scrollWidth === clientWidth`；总览最多显示4个关键标签；当前认识保留可访问短文本。
- 键盘：Tab顺序覆盖导航、视角、图/列表、放大、缩小、适配和关键对象入口；焦点轮廓清楚。
- 列表：3D或WebGL不可用时，用户仍能访问同一节点、关系、来源和返回动作。
- 对比度与字号：深色背景上的节点标签、关系线、未知状态和按钮必须可辨；颜色不是唯一信息载体。
- 减少动态：在操作系统启用`prefers-reduced-motion`时记录CSS媒体状态、相机最终位置和无动画截图。

## 8. 性能与稳定性

性能验收分离“功能可用”和“视觉流畅”，记录设备、浏览器、缩放和图规模。

| 场景 | 通过门槛 |
| --- | --- |
| 基线总览 | 47节点/138关系；WebGL2 ready；正常机器上首帧可交互≤2.5 s（图谱数据返回后开始计时） |
| 常用交互 | 选中、缩放、适配、视角切换的反馈开始≤100 ms；过渡结束≤900 ms |
| 稳定切换 | 三次视角和2D/3D/列表连续切换10次，不丢选择、不崩溃、无稳定构建error |
| 帧时间 | 47/138桌面总览记录至少10秒；中位帧间隔≤20 ms，p95需记录并作为下一轮回归基线 |
| 压力场景 | 200节点/500关系不得崩溃或白屏；允许降级标签/边或回退列表，必须明确状态 |
| 资源 | 3D继续按需加载；不得把3D渲染器、布局Worker或大图数据加入首屏阻塞路径 |
| 内存/上下文 | 连续卸载重挂3D五次后仍能恢复；光晕纹理、Canvas和事件监听有清理依据 |

未设备实测的项目只能记为`not_run`，不能以构建通过代替。

## 9. 量化评分

评分是视觉复核的辅助，不替代硬阻断、语义任务和用户判断。每项0–5分：

| 维度 | 权重 | 5分标准 |
| --- | ---: | --- |
| 整体构图与空间预算 | 15 | 星图成为主角，首屏紧凑但不拥挤，群落形成非对称但稳定的空间 |
| 焦点叙事 | 15 | 当前认识、A/B/D、来源和判断桥梁形成清楚的阅读路径 |
| 群落与关系层级 | 15 | 群落、支持、挑战、导航和未知可从线型/文字/明度区分 |
| 星点材质 | 10 | 色温、内核、光晕、大小和状态环统一，克制且有质感 |
| 文字与卡片系统 | 10 | 标签、说明和笔记有稳定字级/间距，长文本不破坏构图 |
| 动效与操作反馈 | 10 | 入场和交互帮助定位，能中断、能跳过、无持续噪声 |
| 响应式 | 10 | 桌面与手机保留同一任务和语义，手机不拥挤 |
| 可访问性 | 5 | 键盘、列表、真实文本和减少动态均可用 |
| 性能与稳定性 | 5 | 基线与压力场景有数据，正常切换无错误 |
| 参考图一致性 | 5 | 在同一尺寸下，布局节奏、色彩、纵深和视觉密度达到可解释的一致 |

通过门槛：

- 加权总分至少**85/100**；
- 任一维度不得低于3/5；
- 硬阻断项全部关闭；
- T1–T8全部通过；
- 用户对最终视觉明确给出“通过”，不能由实现者自评替代。

评分记录必须写明证据和扣分原因。总分高但存在P0/P1仍判`blocked`。
