**粒度取舍。** 不把全题塞进一个巨型Comparison，也不为每句结论造新对象。一个单元涵盖可一起判断、一起修订的结构/条件；只有独立条件分支确需不同依赖或可独立撤回时才拆。稳定键由host分配并留归属；模型提出“修改已有/增加并列”，不能仅因换标题或研究窗口就换身份。M1先做一个小问题的一个单元，平行分支与局部失效用工程夹具验证，不为凑齐对象调用模型。

Collection随所属Comparison更新并在同一事务发布；不承担全题永久成员全集。旧Comparison版本用于前后对照，不作新版本的关键因果依赖，否则替换自身会错误触发链式失效。导航Wiki不作为“所有认识必须有效”的屏障；当前读取依据Comparison自身有效性，失效分支可见但不能列为可用。

**输入复用与维持。** 研究身份包括问题/范围版本、方法的实质兼容版本、准确新输入、实际旧认识与代表/反例读集、来源质量/有效性、目标baseHeads。事件时间、日报日期、请求键不参与语义输入身份。相同身份先查已知终态，零模型复用；failed/restricted/unknown不会因换日报或请求键自动重试。新证据但结论维持时记录理由和实际读集；若增补了真实依据则发表同一单元的依据版本，不重写其余单元。同原片精拉能补充信息，不能加独立支持票。

**变化含义。** 首次/补充/收窄/纠正或取代/撤回写入现有changeset的effect和explanation；“维持”可只记研究run结果。现有`narrow`只验证Applicability集合收窄，不能拿它证明正文语义被收窄；正文条件修订仍须语义审阅并显式解释。来源失效是立即的技术状态，撤回是有原因的认识决定，两者不合并。

## D. 主要风险与推荐取舍

1. **窗口报告堆积或单一总命题。** 两者都会丢失“当前相信什么”。推荐稳定Comparison单元＋按问题的分页当前视图；窗口只作读集/执行收据。不另做模型全题总述。粒度以可独立修订/失效为准，M1检验后再扩。
2. **别名/通道正确与hash正确混为一谈。** 候选@20仍有红边界。原字段hash只证明读集，语义审核仍检查分句来自帖文、字幕、ASR还是画面；不独听音轨就不称已核听。先修最小源读取器，不把更多审阅轮次当解决办法。
3. **增量只看新片会漏反证，重读全库又不可持续。** 新源＋被影响旧认识＋支撑该条件的代表与反例；引用到但没有完整重读的旧依据只作已审上下文。无法闭合的规律修订保持未决，不强制全库成熟才出描述性认识/日报。
4. **对象级失效过大。** 现有关键依赖会使整个Comparison失效。推荐按可独立条件拆稳定单元，接受该单元保守暂不可用；不在本轮新增句级有效性引擎。Wiki导航不应让一个分支拖下全部当前认识。
5. **日报再次偷偷研究或回流自证。** 编辑只消费已审版本，新增比较走共享入口；日报归档仅为应用上下文，不作支持证据或on_change新依据。按日期显示“今日获得/变化”，另列“今日收录的旧素材”，无变化可以明确维持。
6. **工程成功掩盖内容不足。** M1先看整份受限报告与原资料对照，不等所有对象齐备；M2再验增量/失效；M3才扩大到完整14份、独立冷读/浏览器并准备PR。当前不创建PR、不合并、不交部署，M0后停待原会话具体反馈。
