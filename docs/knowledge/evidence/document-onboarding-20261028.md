## 输入与执行

使用核心提交 `844702c5a3a095d78611c963e3a3fc0f09f9df37` 对应的 `AGENTS.md`，实际文本 SHA-256 为 `3f8bfefdd20deeecb6a1feea32864962ab655a500490e1be18755955e110ce6b`，字节数为 2742。

通过 `npm run test:document-onboarding` 和一次性 PostgreSQL 容器执行：

1. 登记真实文档并重放，确认返回同一准确来源引用。
2. 读回原文，确认文本、摘要和字节数完全一致；元数据不复制托管正文。
3. 查询知识并保存读集，登记采用、暂缓及合成反馈，验证幂等重放不改变使用记录 ID。
4. 撤销文档来源，确认新的正文读取被拒绝。
5. 停止服务并删除临时 schema，输出不含 token 的 `local/document-onboarding/evidence.json`。

实测结果：`queryItems=10`、`replayedSameId=true`、`revoked=true`、`schemaDropped=true`。

## 同时修复的合同问题

首次执行发现：托管原文在 schema 中被 `trim()`，但适配器在修剪前计算摘要。任何首尾带空白或换行的真实文档都会因此出现摘要不一致。

`packages/knowledge-contracts` 的 managed copy 已改为保留原始首尾空白，并在合同测试中增加防回归用例。这样真实文档不会因为末尾换行而被错误改写，摘要与原文保持一致。
