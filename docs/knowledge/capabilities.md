# 知识能力与外部接入合同

外部系统接入的是知识库能力。它可以提供来源、读取准确知识、提出研究问题、记录实际使用和反馈；知识服务负责自己的内容与审阅发表规则。

2026-10-26 · 下表是能力责任目录。具体字段、校验和可调用操作以同一实现版本的共享合同为准；规划中的 30 个建议 HTTP 操作不是已经发布的 API 清单。当前主线版本与部署状态见[当前状态](current-state.md)。

| K03 | 查询与读取 | 有界相关知识、准确版本与读集回执 |

| K05 | 关系与依据 | 有类型的关系、来源路径和有界影响 |
| K06 | 研究问题 | 作业状态、实际读集、结果、缺口及成本 |

### 显式有据问答

普通 `/query` 继续返回候选，未指定方法时保留标题/正文词项 v1；显式 `retrievalMethod: wiki-lexical-v2` 追加结构化身份键和别名。别名匹配是召回信号，不证明同一实体或语义支持。方法版本写入读取回执并绑定分页游标；v1/v2 不能混用游标。工作台只在服务声明 `queryIdentityLexicalVersion: 2` 时启用 v2，以兼容旧服务。

G5 本地候选为当前 Wiki 页头增加可重建的 Unicode 二字 gram 检索投影与 GIN 索引：v1 覆盖规范化标题和正文，v2 再覆盖结构化身份键与别名。它只预筛可能命中的版本；最终仍由原 SQL 的 `position` 词项评分、当前页头及空间过滤、排序和分页决定结果。同一查询语句内检查 `ready` 与格式；未就绪、格式不符、任一词项不足两个 Unicode 字符，或宿主诊断关闭投影时，整次回到原 SQL 扫描。规范化检索字段合计超过 200000 UTF-8 字节的页会阻止所在空间标记 `ready`，查询仍可完整回退。投影不复制知识权威，也不判断用途、来源撤权或语义支持；这些仍由原读取政策和上层流程负责。实现依据：投影与更新触发器 (`packages/knowledge/src/wiki-search-projection.ts`)、查询预筛及原评分 (`packages/knowledge/src/store.ts`)。最终规模与完整回归仍待[当前状态](current-state.md)中的 G5 回执核对。

独立的 `ask` 能力仅在服务端显式注入 `QueryAnswerer`、启用操作账本写者并授予 `ask:write` 时开放。Ask 使用 v2 有界召回。调用者提交问题、用途、候选分页范围、是否回查原文及预算，同时提供固定幂等键。模型只接收当前用途允许的准确页正文、条件、反例、未知及成功读取的文本来源；每项答案必须引用本次读集里的 evidence ID。

答案是临时使用产物，不能直接发表 Wiki。返回结果包含实际证据版本、覆盖/遗漏、成本与提供方回执，并区分 answered、needs_evidence、refused、failed 和 outcome_unknown。每条证据保留自己的条件、反例和未知；引用 ID 校验不证明推论正确，真实语义质量另行验收。当前文本路径不会把来源元数据或帧图当成已经被模型看过的原文。

`POST /ask` 在调用模型前保存准确读集与执行意图；`GET /answers/:id` 按原用途读取，`GET /answers/lookup?key=...&purpose=...` 只读核对原键。查无记录返回 unknown，不证明原请求未提交。超时或中断不自动重发；重读与原键回放都重新核验当前依据和来源权利。此能力的当前实现及未完成项见[实施回执](evidence/wiki-loop-implementation-20261102.md)。

工作台将探索与有据问答分开，默认费用上限 0 USD，来源原文须主动勾选；显示回答、可打开的准确引用、每份依据的条件/反例/未知及实际费用。阅读引用后返回问答会先隐藏缓存答案，再只读核对当前权利；核对失败不继续展示旧回答。

新客户端通过 `capabilities({includeRecoveryScope:true})` 显式请求恢复范围，服务返回与认证主体、安装、项目及空间绑定的稳定摘要。默认能力响应保持旧字段集合，旧服务可忽略协商。恢复摘要只为客户端隔离记录，服务端仍按认证上下文核验每次访问。

工作台在发送前将原键及严格校验的调用者输入保存到当前标签页的 sessionStorage；自动保存范围不含令牌、回答或来源正文。整页刷新、重新认证后，恢复原问题、费用上限与原文选择，并用原键 GET 核对。保存失败、记录损坏或结果未知时阻止新的付费提交；恢复过程不重新 POST。标签页会话结束后的恢复及跨标签页发现仍需另行设计；旧服务不支持恢复标识时明确保留仅内存模式。

Ask 先读取候选版本、大小与存储指纹，再在剩余额度内取得 Wiki JSON 正文载荷；原文必须经过所有者的有界读取端口，不支持时登记缺口。返回的 `readUsage` 区分 Wiki 载荷、来源文本和准备的模型输入。限额覆盖回传到应用的正文数据，数据库内部扫描、元数据及网络协议开销另行计量。调用前记录保存后再次校验依据及变更水位，外部模型分发的授权租约仍由适配器单独保证。

Ask 读集会保留 Wiki 修订的继承来源组；回查外部来源时，先读所有者元数据并带入其来源组，再按准确摘要限额读取文本。组未知时明确记为未知。同一原件的粗拉与精拉报告仍是同一组，不能由报告数量推导独立证据数。

即使没有勾选原文，读取及回放 Wiki 也会递归核验关键来源的当前权限；只取依赖元数据，不下载依赖页正文。关键来源超过检查上限、无法取得完整覆盖、撤权或内容不可读时拒绝继续。本地实现保守要求关键来源 `contentReadable === true`，尚未提供独立于内容可读性的使用授权或跨系统租约；这也不等于其他旧查询/采用入口已完成全部生命周期失效传播。

### 来源事件与实体提及台账

K02 另有显式启用的事件接收路径：来源 owner 保管原件，调用者提交准确版本/摘要及稳定生产事件键；核心只登记元数据和后续 outbox，不把来源变成已审阅知识。重复同键同输入返回原记录，同键改输入拒绝；记录和 outbox 同事务保存。主体、安装、空间、用途及 adapter 都参与权限或幂等边界。当前准入保证仅为 `read_time_only`，不是外部来源的发表许可。

`recordEntityMentions` 需要同时具备 `ingest:read` 与 `ingest:mentions`，并取得该来源当前用途的读取权限。它校验调用方提案的准确 UTF-8 原文跨度，保存派生的 surface 节选与 unresolved 状态；既不自动抽取，也不把名称或类型提案视为已消歧实体。批次的语义覆盖保持 unknown，不生成知识页或推进 head。已完成批次重放只核权限；同方法并发由短事务 claim 拦住，后续写入核对 token/lease。租约过期后允许同键重新进行受限本地读取，旧 token 不得提交；不宣称故障期间原件 IO 恰好一次。

来源事件与提及的读取、lookup 和重放都重新核对原 owner 权限。撤权后不能继续读取派生节选。现有编纂、关系判断和周期 Lint 的能力与边界见下文；自动实体消歧仍待实现。

显式注入的 `SourcePlanner` 可通过 `POST /source-plans` 对一个准确来源事件提出研究问题、查询词和实体提及跨度；按原 ID 或键只读核对。它要求 `source-plans:write`、`source-plans:read` 与 `ingest:read`，在限额内读取有完整覆盖的准确来源文本，冻结来源引用和来源组，并校验提及跨度。提及仅以 `model_proposed`、`unresolved` 留在本次计划提案，不写入调用方提及台账，也不自动消歧。确认的提供方原始响应若为安全 JSON，会先连同已知费用持久化再校验提案；来源正文回显不会被复制到账本。当前只有注入式本地合成提供方，没有真实模型或网络 transport。

### 来源与旧 Wiki 的有界编纂

显式注入 `WikiCompiler` 并启用 source intake 后，可提交准确来源事件、问题与检索词。编纂使用 v2 候选元数据，按统一剩余字节额度回读报告与当前旧页；`limit` 同时限制全局 Wiki 正文读取数，`maxPages` 限制每个检索词的分页。来源原文、Wiki JSON 载荷与准备输入分别计量；准备输入另须落在同一声明额度内，数据库内部IO和元数据开销不计入这些正文计数。

提供方收到准确版本、旧页条件/反例/未知、来源组和注册 profile；每个提案只能引用本次实际读过的 evidence ID。修改目标还须是本次冻结的旧页，保持 profile 与身份 key；准确身份冲突不能自动合并。新路径使用自己的方法与操作来源，不冒充旧 synthetic research。当前验证提供方仍是本地合成实现，没有真实语义验收。

提案先进入编纂账本。仅在关键原始来源具备完整本地事务保证时，可信 stage 适配器才能创建正式待审 changeset；它不推进当前页头。外部 `read_time_only` 来源保留 `draft_ready / blocked_source_assurance`，不因生成成功得到发表权利。新的编纂候选经明确 wiki_compile origin 接入独立审阅；批准时仍需在同一发表事务内重新核对本地来源、输入版本与目标head。外部来源保证未实现，仍不得发表。

执行前持久化读集与调用意图，提案落账后再次检查当前性、权限、水位和期限。来源证明过期时只能在 owner/代次/摘要/主体/用途/受众不变的前提下刷新有效期。未知调用或账单保持 outcome_unknown，不自动重调模型。若候选已 stage 而账本完成失败，原键重放或 lookup 只核对已存在的准确候选并补本地关联，不新建候选。尚未 stage 的已存草稿暂未开放独立的无模型 stage 重试。

外部提供方另需显式且可执行的模型/金额预算，以及宿主提供的资料外发许可回调；本地读取许可不能代替该许可。默认没有内置真实编纂模型，也不会因来源事件到达自动调用付费模型。

### 独立审阅、发表与历史查看

编纂候选通过准确 content hash、stageIntent 和实际 changeset 取得审阅资格；这不放宽旧 synthetic research 的验证。审阅者必须不同于提出者，且有明确审阅 action。候选正文与依据的读取还要求提出者和审阅者均有该用途当前的本地来源权限；审阅 action 本身不授予来源权限。注册时的可信 `sourceReaderIds` 可声明来源读者，不因请求审阅而自动扩权。

候选视图给出准确修改前/后版本、条件、反例、未知、来源组及当前是否可批准。修改前按 baseHeads 的原版本读取，不替换成最新页。若审阅要新增候选里没有的 conditions/gaps，须先改稿，不能在批准时偷偷修改不可变正文。批准、review receipt、唯一发表、编纂状态及票据更新在同一项目锁事务内完成；源撤权、输入过期、目标head变化或中途失败都不会留下部分发表。

发表后的编纂记录和候选可以按历史资格查看，仍递归检查关键来源当前权限；历史可见不表示旧读集仍可采用。条件反例修订 C1→C2 后，依赖准确旧 C1 的 D 会失效，Ask 不再把它交给回答器。新编纂的 no_change 独立审阅、外部 owner 发表保证、尚未stage草稿的单独重试仍待实现。周期维护已有下述元数据能力，尚未自动协调到编纂。

工作台可按候选 ID 只读核对准确前后版本、请求票据，并在独立身份下明确批准发表或拒绝。状态未知时保留原键，只做核对，不自动重发；终态只保留历史入口。维护界面已有任务、发现、检索投影状态、原键只读核对和候选连接；仍不是完整维护收件箱。

### 周期元数据维护与逐对关系判断（2026-11-02 本地候选）

维护任务从已登记来源事件和知识事件按各自游标收集，持久保存任务、尝试、租约、取消意图、分发前状态和已确认响应。执行端丢失租约或外部响应不明时保留 `outcome_unknown` 与未知费用，不能按新键自动再调用提供方。`collect` 只负责受理与推进事件游标；任务是否执行由可选 `MaintenanceProcessor` 决定。默认 Worker 运行元数据收集与 Lint，不内置语义处理器。

周期 `lint` 对当前已发表 Wiki 页头按确定的 UUID 分片和游标逐页扫描，记录七类结构提示：审阅到期、缺失或未发表的知识依赖、无知识边、关键冻结依据失效、缺引文、重复来源组、同 profile 与准确身份键重复。它只读取所需元数据，不读取 Wiki 正文到应用，也不改正式页头或正文。`consistency: incremental_current_heads`、起始与观察 epoch 及遗漏原因说明扫描期间可能发生变化；完成一轮不等于任意时点的全库快照，也不等于已发现语义矛盾。每页的发现、游标和累计数同事务落账；`findingCount` 是累计发现数，`findingIds` 最多 1000 个、仅为最近一页预览，完整条目通过 findings 分页读取。

逐对 `DecisionProvider` 已有显式请求、准确双端读集、预算、受保护的判断账本和 HTTP/SDK 查询与原键核对。返回的是待审关系提案，不自动写正式图谱或把两个来源组当成两票独立证据。Jev/OpenAI codec 只编码、解码 wire data；它不提供 SDK、网络传输、密钥或真实模型调用。

显式配置 `SourcePlanner`、编纂器、维护能力与协调策略后，一个 `source_research` 任务可按持久步骤运行：准确事件规划 → v2 有界旧页发现 → 最多三次有类型的双端判断 → 将本次真实读集中的判断作 advisory hints 交给编纂器。结果可形成待审候选，不自动发表。每步固定原键、请求和预算，共享最多五分钟的总期限及费用、调用、读取额度，按已确认回执累加；未知只核对原操作，不换键重调模型。任务普通 reason 不承载私有模型内容，协调详情与计划每次读取重验来源资格。独立审阅在同一事务关闭编纂、协调运行及任务；批准与拒绝都结束任务，但编纂结果不同。租约仍在运行时不抢占，过期 ACK 按真实发表或拒绝结果核对。周期旧 Wiki 的语义发现与重编纂、查询高价值回答回流、统一实体消歧、无变化提案的独立审阅及外部业务 owner 发表保证仍待实现。

## 接入前先确定的输入

| 输入 | 约束 |
| --- | --- |
| 身份与范围 | 服务端认证主体、安装、部署项目、空间和来源权限共同约束；请求正文不能自行授予权限 |
| 用途 | 阅读、研究、创作执行等用途按服务政策批准，不由调用者随意换字符串解锁 |
| 准确引用 | 保留原对象、版本与摘要；当前选择器先解析为准确版本，不静默换成最新版 |
| 来源 | 作者、发布者、取得者、观察或来源主张分别记录；同一原件的多份报告不增加独立证据数 |
| 外部上下文 | 使用业务自己的任务身份与版本，知识服务不要求业务复制成内部任务 |
| 写入前提 | 准确输入、预期页头或版本，以及需要的幂等键；具体格式由共享合同校验 |

## 读取与写入的边界

普通查询不隐式采集、收费研究、采用或发表。结果说明实际范围、是否还有下一页、遗漏原因及来源可读性；有界无匹配不能解释成全库没有知识。

来源读取只取已登记的准确版本与允许锚点，检查摘要、字节范围和用途，不跟随任意地址重新抓取。历史可读与当前可采用分别返回。

业务原件可以保留自己的来源域，通过业务所有者的只读端口读取。原对象、版本、定位器和权限仍归业务所有者管理；知识产品不能静默换成最新版或另一份副本。可读性应区分所有者未连接、不支持的内容或定位器、禁止访问、仅元数据和内容已读取。版本记录的摘要、所存对象的字节摘要及实际返回内容范围需要各自说明，不能用其中一个替代另一个的核验。

写入通过幂等操作回执追查。相同键和相同输入对应同一操作；相同键的不同输入发生冲突。网络超时不能解释为未执行，未知结果按原操作或原键对账，不能换键重复发起外部调用。前端保留原输入和原键并锁住新提交，只读核对完成后再恢复操作。查无记录本身也不是未提交证明。

用途贯穿反馈、使用关联、操作查询、阅读回执、研究、审阅与取消。后续读取或对账须携带原用途，不能用另一项已获批用途访问旧操作；当前来源权利仍须重新检查。本地输入校验失败明确表示未提交，和传输结果未知分别处理。

## 异步状态与错误处理

接收作业只说明已受理。执行状态、认知结果、审阅状态与发表状态分开；研究可得到候选、不变或待补证。取消请求等待执行端确认，已经发生的费用和未知结果保持可见。

客户端应区分无权或不可见、输入不受支持、准确版本冲突、来源不可读、用途不允许、预算受限和外部结果未知。先依据返回的提交状态、重试政策与操作回执处理，不用统一“再试一次”按钮覆盖差别。

## 两种最小接入场景

普通文档可以从固定修订、原文或允许节选、页段锚点和读取范围开始；视频业务则把准确报告、原片身份、秒点与观察范围交来。两者共用 K02–K05，后续通过 K09–K11 记录使用与反馈。

新业务的源码准备、构建运行和普通文档端到端步骤见[技术接入手册](integration.md)；commerce 字段映射及交接顺序维护在[业务适配指南](https://github.com/cyl19970726/commerce-creative-lab/blob/main/docs/integrations/knowledge.md)。公开 schema 确认后，从该权威生成字段参考与示例校验，不再手写一套并行 DTO。
