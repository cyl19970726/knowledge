# 知识产品的职责与架构

独立前端与业务系统使用同一组知识能力；知识服务保持唯一的版本、关系、审阅和发表权威。拆分先在同一仓库中建立明确依赖和独立运行入口，拆仓、拆库及生产切换分别判断。

2026-10-26 · 本页维护架构方向。当前主线实现、固定历史版本和正式部署见[当前状态](current-state.md)；历史细节见[原业务架构说明](reference/commerce-architecture.md)。

## 四部分怎样协作

| 部分 | 拥有的责任 | 通过什么连接 |
| --- | --- | --- |
| 独立前端 | 探索、正文阅读、研究、来源与演化，以及视图和返回状态 | 知识客户端与公开合同 |
| 知识后端 | 知识版本、关系、依据、研究策略、审阅发表、采用与反馈 | 应用服务、核心规则和设施端口 |
| 业务适配 | 平台身份、采集、拉片、原始媒体、业务任务及效果记录 | 登记准确来源、查询知识、登记采用反馈 |
| 共享设施 | 模型执行、任务租约、取消、费用账本、数据库和对象存储 | 实现知识应用层所需端口 |

知识研究可以提出缺少什么资料，业务系统决定并执行自己的采集和分析。查询知识不会自动取得平台操作、付费模型或经营执行的权限。

## 分包与构建

公开 DTO 和运行时校验只有一个权威来源，供前端、客户端、后端及业务适配共用。客户端保持运行时中立，不引入 React、数据库、视频分析或业务表。前端只依赖浏览器安全入口；后端通过应用层协调核心与设施。

首版图谱作为独立前端内有明确接口的模块，分别处理语义投影、布局和相机状态。页面位置和聚类是展示结果，不能写回为知识事实。图数据库不是前端拆分的前置条件。

每个独立应用或包都要有清楚的构建入口和产物；目录分开不等于能独立构建。浏览器构建不能要求视频 Worker、生产数据库或模型配置。包名、导出和命令以对应实现版本为准，本页不维护第二份清单。

## 数据与来源所有权

知识服务拥有登记后的准确来源引用、知识版本、关系、研究记录、审阅和正式发表。业务系统保留原片、原始报告、平台凭据及经营记录；普通资料明确采用托管副本时，知识服务按自己的保留与访问政策管理。

业务变更或撤销来源时，通过来源生命周期交接通知知识服务。来源元数据可见、内容可读、锚点可定位、依据有效、当前用途允许是不同判断。

外部来源当前可读，不意味着发表提交时仍有权使用。外部所有者若不能提供可证明的用途保证，不能宣称跨系统撤权与数据库提交天然原子；本地托管来源则须在发表事务内重验版本与权利。

### 旧业务来源的只读接入

旧分析报告和帧证据继续使用原 `analysis/evidence` 对象及准确版本。业务所有者解析自己的报告、媒体身份和定位器；知识应用通过显式配置的认证只读端口取得允许的内容。接入读取器不需要将旧原件重新登记为一份托管知识来源，也不能改写已有知识的引用。

来源元数据、实际正文或帧内容、读取覆盖分别返回。仅打开图谱或查看来源身份不算内容已读；读到一张离散帧不代表看完一段视频。同一原片的多份报告或重复帧仍属于原来源链，不增加独立证据。

这个端口的访问保证限于当次读取。它不授予采集、媒体处理、研究执行或发表权限；撤权后的新读取仍由业务所有者判断。具体已接通范围和验收结果维护在[当前状态](current-state.md)。

## 阅读、研究与唯一发表

查询返回有界结果及准确读集。需要保存和复用这次阅读时，使用持久回执固定实际对象、版本、顺序、范围与当时判断；日后访问仍检查当前权限。当前指针、历史版本和查询回执分别管理。

研究策略由知识应用层控制。执行端负责租约、尝试次数、取消、费用与外部未知结果；候选经独立审阅后，发表端在同一事务内检查写者资格、准确输入、依赖、目标页头、取消及审阅证明。

任务尝试的 fencing 不能代替发表权限。旧入口和新入口都必须归到同一权威；业务客户端不直接写表、修改页头、签发审阅凭据或任意发表。

## 分阶段交付

M0 收敛合同、权限、准确读集和写者边界；M1 建立独立读取入口与前端；M2 接来源写入、研究、审阅及本地 API/Worker；M3 接通用采用反馈和不同业务适配。每阶段都按实际证据登记，不能从阶段名称推断完成。

正式切流与部署属于 M4 条件阶段；是否拆数据库或仓库属于 M5 条件阶段。本轮文档与本地工程交付不自动触发这些动作。
